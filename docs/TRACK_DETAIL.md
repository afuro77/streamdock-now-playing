# Spotify Track Detail (DEV)

Press normal top-right LCD to enter Track Detail at TRACK. Right small knob rotation cycles TRACK → ARTIST → ALBUM, reverse rotation reverses the order. Normal Now Playing seek/shuffle behavior is unchanged. BACK returns directly to Now Playing; HOME also returns Home. LCD press still exits the full-screen view. Existing inactivity timeout remains. Right small knob press keeps its existing Shuffle action.

TRACK delegates unchanged to the existing title/artist marquee renderer. ARTIST displays the complete image with aspect ratio preserved, fitted into 384×216 with letterboxing; a separate 40px name band keeps text off the photo. Multiple artists are stored separately and rotate every eight seconds with an index. Missing images/API errors show the GSMTC artist name and a fallback message. ALBUM shows album name using the existing upper-row scrolling renderer and year / track count / total track time on the bottom row. Multi-disc track numbers remain disc-local; total_tracks is album-wide. Release year describes this album edition, not necessarily the original composition/release year.

Optional enrichment lives in track_details.py and detail_renderer.py. It uses the existing PKCE token and adds no scopes. API/network calls and photo downloading run in a worker thread, not the Stream Dock event/render loop. Enrichment only requests while Track Detail is visible. Playback is rechecked at most once per 15 seconds for unchanged metadata; identity changes invalidate published data immediately. Current Spotify track title/duration must match GSMTC before publishing. A response for an older GSMTC identity is discarded. Service completion can only update its own data, never active mode, view mode, or device images. Switching to Desktop is independent.

Bounded process-local caches: Track ID → metadata (64), Artist ID → metadata (32), Artist ID → decoded-source image bytes (24), plus bounded rendered-photo frames. Successful photos/metadata are reused across songs with the same artist. Cache is not persisted to source or Git. Image fetches use trusted HTTPS scdn.co URLs, timeout and byte/dimension limits. No credentials are sent to image URLs. 429 honors Retry-After through the existing Spotify client and service backoff. Authentication/network errors do not call media commands and do not disable GSMTC controls.

Live check confirmed matching metadata and an artist image for a currently playing track. Preview artifacts are outside the source repo. Tests cover pages, no seek leakage, matching/new tracks, obsolete in-flight completion, auth/network/429 failures, no/bad images, multiple artists, caches and Desktop rendering isolation.

Spotify-sourced photo/metadata display must retain applicable Spotify attribution/link handling for any future distribution; this DEV change is a local prototype. API: https://developer.spotify.com/documentation/web-api/reference/get-an-artist and https://developer.spotify.com/documentation/web-api/reference/get-track .

Artwork entry update: pressing any left artwork LCD starts on full artwork, then right small knob cycles ARTWORK → TRACK → ARTIST → ALBUM (reverse supported). Entering from top-right still starts TRACK and cycles only three metadata pages. BACK from either expansion returns directly to Now Playing. Right dial rotation in artwork now navigates pages instead of seeking; normal-screen seek and dial press shuffle remain unchanged.

Unified entry behavior: both artwork and top-right title enter the SAME four-page ring ARTWORK → TRACK → ARTIST → ALBUM → ARTWORK. Only the initial page differs: artwork starts ARTWORK; title starts TRACK. This supersedes the earlier three-page title-entry behavior.
